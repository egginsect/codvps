## Carried review findings

The reference M1 pull requests carry no GitHub-side review threads (checked 2026-09-27). The substantive review findings are restated here, one line each, as acceptance items:

**Carried from the reference review:**
- Syntax gate: `bash -n a b c` only parses `a`; check every remaining shell file individually, with a mutation test proving an error in a non-first file still fails the gate.
- Diagnostics: capture sanitized journal, service and test logs *before* tearing down a failed fake-VPS container, since a `docker ps` after deletion can't recover them.
- Honest offline claims: separate network-dependent provisioning (image/dependency installs) from hermetic behavior tests instead of describing the whole job as offline.
- No-private-bootstrap regression: port as a success-path test — a deterministic successful-auth fixture, an assertion the flow reached its end, clone/bootstrap calls captured in an operator-writable log, and a check that reintroducing a clone makes the test fail.

**Carried from the reference review:**
- Keep key-generation tool output (progress, fingerprint, randomart) separate from the selected key path; test both passphrase choices, cancellation, an existing pair, and invalid/symlinked paths.
- Detect `gh` auth from structured state (`gh auth status --json`) plus the host's identity API, not by grepping an English sentence; handle multiple accounts, env tokens, and `GH_CONFIG_DIR`; never enroll a key for an unknown account.
- Use one key-enrollment flow (`gh auth login --skip-ssh-key`) so `gh` never creates/uploads a different key than the one codvps previewed; verify scopes via supported upstream behavior, not scope text.
- Report credential storage as file/keyring/env/unknown without reading or printing tokens and without YAML-grepping a single path; a plaintext-fallback advisory is not a missing-login step.
- Verify the selected key is what the effective SSH config actually uses (`ssh -G github.com`, including Includes/aliases), not merely that some `Host github.com` block exists; pending/skipped key setup must not run a failing SSH check or report Ready.
- Install approved missing prerequisites (git, openssh-client, gh) through shared codvps operations instead of exiting with an "install X" message; expose a small ready/pending/failed result for and.

**Carried from the reference review:**
- Source identity: a reused local checkout must match the selected source; switching the requested URL must not silently fetch the checkout's unrelated existing origin; verify source/ref/profile against the staged revision before apply; redact URL-embedded credentials from all output and state.
- Visibility inside the Codex namespace: removed with the namespace (owner decision).
- Sentinel fixtures: plant a malicious `install.sh` and a source-to-workspace sentinel, and prove neither executes nor attaches during connect or sync; also test an existing checkout with the wrong origin.

**Carried from the reference review:**
- Bootstrap is not the all-tools installer: a fresh bootstrap installs only codvps and explained Git/SSH/hosting-CLI prerequisites; coding tools install only after the identity gate, source selection, and component review; test zero selections, Claude-only, Codex-only, and cancellation-before-selection from a truly empty host.
- Keep desired and observed state separate from the supported inventory: `update all`, doctor, runtime seeding, service generation and uninstall act only on selected/adopted components, never on every supported one; never remove pre-existing user-managed installs that are unselected.
- Pass target context explicitly: every operation receives operator, verified executable, config home, work target and ownership; environment overrides such as `CODEX_HOME` are scoped to one child process, never exported globally; test with ordinary and Remote homes and conflicting inherited environment variables.
- Keep the shared result contract small: component, capability, ready/pending/failed/unsupported, a non-secret next action, and restart impact.
